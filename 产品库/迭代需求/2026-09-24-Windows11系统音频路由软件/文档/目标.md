## 2. 业务目标与产品目标
- 业务目标：当我和好友语音/游戏连麦时正在电脑上听歌或看视频，我想要把电脑里正在播放的声音连同我的说话声一起传给好友，并且能随时挑选共享哪个应用的声音、调大调小它传过去的音量，以便我不打断聊天就能"给朋友放歌/放视频声音"，好友听得清楚，我自己本地听感不变，我的说话也不受影响。
- 产品目标：本次只解决【Windows 11 上一款个人自用工具：按应用粒度选取一个或多个音频输出源，将所选应用音频与真实麦克风人声混合后送入一个虚拟麦克风设备，供聊天软件选用；每个源有独立共享音量控制；本地扬声器/耳机播放不受影响；配置极简、开机即用】；明确不做【音频特效处理（变声/混响/EQ）、录音功能、多用户/商业化分发、macOS/Linux 支持、系统级音质增强】。

## 3. 真问题
- 电脑上正在播放的声音没法直接"递"给正在连麦的好友：想分享时只能口头描述"你去搜一下"，分享不出去。
- 现有通用工具（VB-Cable + Voicemeeter 一类）配置极其复杂、容易翻车：为了偶尔分享一次声音，要理解虚拟设备、混音器、路由矩阵等概念，配置错了还没声音，试错成本远高于分享欲本身。
- 分享出去的音量没法单独控制：要么盖住人声、要么小到听不见，调音量还会连带影响自己本地听感。

（真问题不含系统、页面、按钮等功能名词 ✔）

## 5. 本次做 / 明确不做
### 本次做
- Windows 11 兼容的个人自用桌面工具（含虚拟音频设备能力，技术路线在方案阶段定）
- 按应用粒度枚举当前有声音输出的程序（如网易云、抖音、浏览器），可勾选一个或多个作为共享源
- 每个共享源独立的"发送给好友的音量"滑杆，实时可调
- 混合模式：所选应用音频 + 真实麦克风人声 → 虚拟麦克风设备，聊天软件把输入设备切到该虚拟麦即可
- 本地扬声器/耳机播放不受影响（音乐照常自己听）
- 简单的共享总开关（一键停止/恢复全部共享）
- 极简配置：装好即用，不需要理解虚拟设备路由概念

### 明确不做
- 变声、混响、EQ 等音频特效
- 录音/回放保存功能
- 音频格式转码、音质增强类功能
- 商业化分发、多语言、安装包品牌化
- macOS / Linux / Windows 10 及以下适配
- 手机端

## 6. 影响与待确认项
### 边界判断
- 是否影响其他组织/系统：不会影响（个人自用工具，独立于公司系统；但需注意安装虚拟音频驱动需要管理员权限并修改本机音频设备列表，仅影响用户本人电脑）
- 判断理由：不与任何森马/外部系统集成，纯本机音频链路工具
- 高风险识别：基建（虚拟音频驱动安装属于系统级组件变更，需在方案阶段评估选型：自研驱动 vs 复用现有虚拟设备 + 混音控制层）

## 7. 验收基线
- 假如【用户 Windows 11 电脑已在运行语音聊天软件并连麦，同时网易云音乐正在播放、抖音正在播视频】，当【用户在工具中仅勾选网易云并开启共享，把聊天软件输入设备切到本工具虚拟麦】，那么【好友端同时听到用户说话声与网易云音乐声，且听不到抖音视频声；用户本地耳机里音乐、视频、系统声音一切照常；用户说话不受任何影响】。
- 假如【网易云与抖音同时被勾选共享】，当【单独调低抖音源的共享音量滑杆】，那么【好友端抖音声音变小/关闭，网易云声音与人声不变，用户本地听感不变】。
- 假如【任意共享进行中】，当【点击共享总开关关闭】，那么【好友端音乐声消失、用户人声正常，用户本地播放不受影响】。
- 假如【全新安装后首次使用】，当【按引导完成设置】，那么【首次配置 ≤ 5 分钟达到上述共享效果（目标值，待实测校准）】。
- 假如【共享开启】，当【长时间使用（≥1小时）】，那么【无回声/啸叫、无爆音、无内存持续增长、无额外可感知延迟】。
- 事实或数字基线来源：用户口述期望（≤5分钟、无回声等为验收目标值非既有事实基线）；现有工具基线待补。
