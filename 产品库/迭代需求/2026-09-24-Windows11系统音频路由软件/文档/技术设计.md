# 技术设计：AudioRouter（Windows11系统音频路由软件）

> 全新工程，无既有代码。以下所有符号均为**新增**。Tier 2 完整概要设计。

## 1. 整体架构设计

```
┌────────────────────────── AudioRouter (Tauri 2 桌面应用) ──────────────────────────┐
│                                                                                   │
│  前端 (Vue 3 + TypeScript)                    Rust 核心 (src-tauri)               │
│  ┌──────────────────────┐                    ┌──────────────────────────────┐    │
│  │ MainWindow.vue        │  Tauri command/   │ audio 模块                    │    │
│  │ ├ AppDropdown.vue     │  event 总线       │ ├ capture.rs  按进程捕获      │    │
│  │ ├ SharedPanel.vue     │◄─────────────────►│ ├ mixer.rs    混音引擎        │    │
│  │ ├ MicSelect.vue       │                   │ ├ virtual_dev.rs 虚拟声卡管理 │    │
│  │ └ Onboarding.vue      │                   │ └ device_enum.rs 设备/应用枚举│    │
│  └──────────────────────┘                    └──────────────────────────────┘    │
│   托盘常驻（tauri-plugin-tray）                配置持久化（tauri-plugin-store）     │
└───────────────────────────────────────────────────────────────────────────────┘
        │                                        │
        ▼                                        ▼
  本地扬声器/耳机（不干预）          VB-CABLE 虚拟麦克风（写入混合流）
```

音频数据流（核心链路）：
`[每勾选应用: WASAPI Process Loopback PCM] ×N → 各自音量乘法 → 求和混音 + [物理麦克风 PCM] → WASAPI Render → VB-CABLE Input → 系统呈现为"AudioRouter 虚拟麦"录音设备 → 聊天软件读取`

本地播放链路完全不经本应用（应用只旁路复制 loopback 流），保证本地听感不变。

## 2. 技术栈选型

| 层 | 选型 | 理由 |
|---|---|---|
| 应用框架 | Tauri 2 | 安装包小（~5MB）、内存占用低、Rust 后端直接调 Windows API，适合常驻托盘工具 |
| 前端 | Vue 3 + TypeScript + Vite | 用户本人技术栈（Vue 可独立干活），后续可自行维护 |
| Windows 音频 API | windows-rs (0.58+) 的 WASAPI 绑定 | Process Loopback（AUDIOCLIENT_PROCESS_LOOPBACK, Win10 2004+/Win11 支持）按 PID 取声，无需驱动、无需 hook |
| 虚拟声卡 | VB-CABLE（复用，个人免费） | 成熟稳定；本应用只负责检测/引导安装/校验 |
| 配置存储 | tauri-plugin-store（JSON） | 每源音量、勾选状态、麦克风选择持久化 |
| 打包 | tauri build（NSIS 安装包） | 单 exe 安装；虚拟声卡安装器作为资源内嵌，首次引导时提权运行 |

## 3. 核心业务主流程

1. 启动 → device_enum 枚举采集设备（填充麦克风下拉）+ 检测 VB-CABLE 是否安装（按设备名 "CABLE Input" 检索渲染端点）
2. 未装 → 触发 Onboarding 三步引导；已装 → 主界面就绪
3. 用户勾选应用（下拉复选框）→ capture.rs 为该 PID 建立 Process Loopback 会话（独享模式，事件驱动）
4. 各捕获线程将 f32 PCM 帧推入 mixer 的无锁环形队列（crossbeam 或 rtrb）
5. mixer 以 10ms 为周期拉取：每源 × 音量系数(0.0–1.0) → 饱和加法求和 → 与麦克风帧相加 → 写入 VB-CABLE 渲染端点（共享模式）
6. 电平计算：mixer 每周期计算各源 RMS → 事件总线推给前端电平条（30fps 节流）
7. 取消勾选/应用退出/总开关关闭 → 停止对应捕获会话，mixer 自动剔除断流源

## 5. 数据库设计

不涉及（无数据库；配置以 JSON store 持久化：`{ selected_apps: [pid临时], app_volumes: {name: 0-100}, mic_id, master_on, onboarding_done }`）。

## 6. 缓存设计

不涉及（无网络/无缓存层；音频环形缓冲属于运行时内存，见异步流程设计）。

## 7. 异步流程设计

- 每个共享应用 1 个捕获线程：WASAPI 事件驱动（AUDCLNT_STREAMFLAGS_EVENTCALLBACK），缓冲 20ms，读到帧即推入该源的 rtrb 环形队列（容量 100ms，满则丢最旧防延迟累积）
- mixer 1 个音频主线程：10ms tick，逐源拉取→乘增益→饱和求和→加麦克风帧→写 VB-CABLE（共享模式渲染，事件驱动写满即写）
- 麦克风捕获独立线程，同样环形队列送 mixer
- 前端电平事件：mixer 每 tick 计算 RMS，经 Tauri event（`emit("level", {pid, rms})`）推送，前端 30fps 节流渲染
- 设备热插拔：注册 IMMNotificationClient 回调 → 端点变化时通知 mixer 重建捕获会话（TC-013）

## 8. 稳定性设计

- 单源故障隔离：某进程捕获失败/格式异常只暂停该源，不影响其他源与麦克风
- 自动重协商：格式不匹配时以 mix format 重新 Initialize，连续 3 次失败暂停该源并上报
- 睡眠恢复：监听 WM_POWERBROADCAST，恢复后全链路重建，失败给"重新连接"按钮
- 内存：环形队列定容；PCM 帧零拷贝传递，无累积分配
- 饱和限幅：混音输出 clamp 至 [-1.0, 1.0]，防爆音

## 9. 配置项设计

| 配置 | 默认 | 说明 |
|---|---|---|
| app_volumes | 各应用 80% | 每应用共享音量，按进程名持久化 |
| mic_id | 系统默认 | 物理麦克风端点 ID |
| master_on | true | 总开关状态 |
| onboarding_done | false | 首次引导完成标记 |
| autostart | false | 开机自启（tauri-plugin-autostart） |

## 10. 容量预估

单用户桌面工具：典型 2–5 个共享源 + 1 麦克风；48kHz/32bit float 双声道下每源 ~384KB/s，5 源 + 混音缓冲 < 5MB 内存；CPU 占用目标 < 2%（单核）。无并发/无服务端容量问题。

## 11. 兼容与回滚

- 兼容：仅 Windows 11（依赖 Win10 2004+ 的 Process Loopback，Win11 全版本满足）；VB-CABLE 需 43xxx 以上版本
- 回滚：应用退出即停止全部捕获与写出，虚拟麦仅剩静音/原声卡行为，无需卸载；卸载本应用不影响 VB-CABLE（可另行卸载）
- 构建：`cargo test`（Rust 单测）+ `npm run build`（前端）+ `tauri build`（打包）

## 12. 自测与风险

自测：
- Rust 单测：mixer 音量乘法/饱和求和/断流剔除（纯函数可测）；device_enum mock 设备列表
- 前端：组件测试（Vitest + Vue Test Utils）：下拉多选/摘要/限高滚动/滑杆
- 集成自测：本机播放音频 + VB-CABLE + 系统自带"录音机"录虚拟麦回放验证（对应 TC-001/002/003）

风险：
| 风险 | 等级 | 缓解 |
|---|---|---|
| 部分应用（如 Chrome 多进程）音频会话归属主进程，PID 归并需处理 | 中 | capture 按进程组（同一可执行名）聚合所有音频会话 |
| UWP 应用 loopback 行为差异 | 中 | 枚举时过滤 UWP 包进程，列表只显示已验证可捕获进程 |
| VB-CABLE 安装需 UAC，用户拒绝 | 低 | 引导停在第一步并说明（PRD 已定义） |
| 系统独占模式占用导致捕获失败 | 低 | 捕获走共享模式 loopback，不受独占渲染影响 |
